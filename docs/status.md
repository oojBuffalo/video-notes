## 3. What the command actually does

- **Measured — current `vnotes.py`:** One executable standard-library Python script. Options: URL, required new `--out` directory, optional `--prompt`, `--engine codex|gemini`, `--model`, and Gemini-only `--review-model`. It is not a yt-dlp flag, plugin, or installed agent skill.
- **Measured — code:** Fetches metadata with `yt-dlp --ignore-config`; chooses English JSON3 captions; requires an available 1080p H264 HTTPS or HLS stream. It downloads neither a full audio file nor a full video file. There is no speech-recognition fallback.
- **Measured — code:** Acquires 48 uniformly spaced JPEG frames using up to 24 concurrent ffmpeg processes. Direct-stream errors can fall back to HLS. No scene detection, perceptual deduplication, transcript-guided selection, or slide-completeness assessment exists.
- **Measured — code:** Uses publisher chapters, merges the first two if the second ends within 600 seconds, and groups more than six chapters into at most six contiguous time buckets. A chapterless video remains one synthesis job. Captions and frames are assigned by their starting timestamps.
- **Measured — code:** Default engine runs up to six concurrent `codex exec` calls, each with structured output and supplied images, using existing authentication, ephemeral/read-only mode, `/tmp` as cwd, and `--ignore-user-config`. It asks for six points per section. The no-tools/no-browsing rule is a prompt instruction, not a tool-disable enforcement mechanism. This is one synthesis pass per section, not the Gemini draft/review chain.
- **Measured — code:** Gemini uses the same local captions/frames, with a draft then a review request per section. It does **not** implement the council's native YouTube URL path. Gemini defaults are model names selected during the earlier experiments, not newly checked availability guarantees.
- **Measured — code:** Validates supplied evidence IDs, chapter membership, nonempty points, and a minimum count of points marked visual with frame citations. Renders timestamp links and cited images. Concatenates section overviews and limitations; there is no global editorial consolidation pass.
- **Measured — saved results:** YC 81:42: **49.167 s**; vectors 9:51: **33.254 s**; Warp 20:36: **37.957 s**. These include fresh acquisition and all report zero cached input tokens. Aggregate input tokens were respectively **279,694**, **220,535**, and **274,228**. See [validation](validation.md) and each `runs/*/result.json`.
- **Measured — verification:** The final three outputs were not manually edited. Targeted image/claim checks passed; not every claim was verified. Nine unit tests pass on this status date. No new live model run was made for this brief.
- **Measured — layout:** Tool/tests/docs are separate from ignored `runs/` and `.local/`. The full old experiment workspace was archived in `.local/benchmark-history.tar.gz`; 1,438 file hashes were checked before removing the loose originals. Historical scripts in runs are snapshots, not alternative entry points.

## 4. Known defects, limitations, and unverified claims

- **Measured — observed earlier failures:** Whole-video Gemini calls timed out, truncated output, or returned provider errors. Its fast frame pipeline sometimes reversed chart comparisons or lost qualifications. A cached native-video success was not a cold success. The first Warp run timed out with 29 short chapters; grouping fixed that tested case. These failures remain in the archive.
- **Measured — code / coverage limitation:** Fixed 48-frame sampling leaves roughly 102 seconds between samples on the 81:42 example. There is no guarantee that a short diagram appears in an input frame. Captionless, non-English, non-1080p, live, private/authenticated, local-file, and general non-YouTube support have not been demonstrated. “LLM of choice” is currently limited to Codex and Gemini integrations.
- **Measured — code / deadline defect:** This is a budget, not hard process-wide cancellation. Executor context exit waits for workers; socket timeouts are not a strict total wall-clock deadline. Codex descendants are not explicitly managed as a process group. The last deadline check precedes writing notes; `complete` may be true while the later `under_60` result is false. JSON/Markdown writes are not atomic, despite t10's recommendation.
- **Measured — code / boundary defects:** Caption selection can reject a preferred English track lacking JSON3 without trying other English candidates. A timed-out direct ffmpeg attempt raises before trying HLS. Frames are rounded to integer seconds, which can land at the end of very short videos. Publisher chapters are trusted without validating gaps, ordering, duration, or full coverage. These are inspection findings, not reproduced failures in all cases.
- **Measured — code / quality gaps:** A citation ID existing is not proof that it supports the claim. The model self-labels whether a point is visual. Six bullets per section are fixed regardless of length; merged titles and concatenated overview/limitations can be repetitive. Prompts contain biology-specific cautions inherited from the first test. The first-two-chapters merge is a heuristic, not semantic detection of an introduction.
- **Measured — code / reproducibility gaps:** Codex metrics store “Codex default” unless a model was explicitly supplied; that default can change. Models and executable versions are not pinned in the main result record. The Codex branch unnecessarily constructs base64 Gemini image parts that it does not send. Logs retain historical absolute paths after workspace cleanup. Output directories are new-only; no cache reuse or rerender mode exists.
- **Assumed — unproven:** Three selected successes do not establish latency percentiles, failure rates, completeness across diagram types, acceptable operating cost, or reproducibility across machines/accounts. Zero reported cache tokens does not establish absence of every provider-internal optimization. Read-only Codex plus a prompt is not proof of prompt-injection isolation. No broad security or cost audit was completed.
- **Assumed — completion status:** This is a useful measured prototype, not evidence that all of the user's original requirements are finished. In particular, the user never accepted dropping audio transcription, broad model choice, or comprehensive visual coverage.
